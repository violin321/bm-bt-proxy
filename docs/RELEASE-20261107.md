发布前重新通过统计单测 8 项、真实本地后端 9 组、原功能浏览器 26 项和概览浏览器 9 项。公共镜像另用生产数据的独立副本完成 9 组真实接口检查：两个源、去重、鉴权、GET/POST 别名、受控上游 401、超时、部分失败、统计持久化，以及重启后的历史和 Cookie。测试脚本原先假定今日和七日请求数相同，跨午夜数据使该假设不成立，已改为同一时区的七日范围覆盖今日后重跑通过。没有为此更改应用代码。

正式切换前做新备份，数据库使用 SQLite backup 获取一致快照。只重建 `bm-bt-proxy`，原数据挂载、两条上游网络、账号环境变量及当前生产配置保留。源配置和 API Key 的配置文件逐字节一致；切换前登录 Cookie 有效，原请求记录保留，SQLite quick_check 为 ok。现有 Byte-Muse、AVDB 和隔离 Byte-Muse 均未因生产提升而重建。

生产实际检查：AVDB 8 条、修仙 6 条，按原有规则去重后 8 条，两个源均为 HTTP 200；`/api/torrents` GET 和 `/bt/api` POST 返回实际结果，无认证管理接口拒绝访问。原记录中 AVDB 曾为 2 条，源站实时结果有变化，不能以旧条数固定判定源异常。

正式 Tailscale 和公网实际 Chromium 均完成登录、四个工作页、360／390／768／1440 宽度、源编辑打开与取消，未发现横向溢出或未捕获 JS 异常。部分 urllib 和 Playwright APIRequestContext 请求遇到连接关闭，但 curl 取得公网 OpenAPI HTTP 200，实际公网浏览器完整验收成功；客户端差异的根因未确证，没有改动路由或服务网络。

Byte-Muse v1.32.0 隔离实例在切换后使用实际网页搜索六种大小写／无横杠写法，各显示相同的 8 条结果；聚合端六条记录都收到 `SSIS-586`，均为双源 complete。没有点击下载或订阅。扩展 14 种格式的结果见 `BYTEMUSE-SEARCH-20261106.md`；数字前缀、空格、后缀等并非都支持等价搜索。本轮最初的隔离消费端空列表定位为未携带当前生产 API Key 的 401；仅同步隔离实例鉴权，未修改生产鉴权或原 Byte-Muse 配置。

验收后移除 `bm-bt-proxy-stage` 和临时 `18008` 监听；保留独立 Byte-Muse 比较实例。临时本地生产浏览器凭据文件已删除。物理手机、持续弱网、长时间运行及所有封面可用性仍不在已完成验收范围。
