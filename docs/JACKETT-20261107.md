# Jackett 原生数据源与返回顺序

BM-BT 1.5.0 增加原生 Jackett 支持，无需额外适配容器。查询方向为 Byte-Muse → BM-BT → Jackett → 已配置站点。通用 API、登录、访问密钥、原源 ID 和历史保持兼容。

## 配置

数据源编辑选择 Jackett，基础地址填写 `http://jackett:9117`，不要粘贴带 API Key 的完整搜索地址。API Key 单独填写；保存后的管理响应仅返回是否存在密钥。再次编辑留空保留、填写替换、勾选清除才删除。可按需填写独立请求头，支持 JSON、Token 简写和键值编辑。

默认搜索范围 `all`，查询全部已配置站点。读取站点列表只说明站点已配置，不表示健康；也可选择一个站点。默认超时 20 秒，可调整；空白关键词不会调用 Jackett。all 尚未响应时超时，本次 Jackett 结果不可用，其他源仍可返回。不会自动重试、自动禁用站点或更改 Jackett 配置。

测试和概览区分全部成功、部分成功和全部失败，可展开内部站点状态。HTTP 200 不等于业务成功。原始站点异常可能含凭据，因此只展示脱敏的错误分类，详细错误到 Jackett 查看。内部站点诊断随既有有界请求历史保存。

映射真实磁链，合法 InfoHash 可生成磁链；只有种子下载地址的记录暂不输出，诊断中显示跳过数量。保留原 Tracker 为 site，大小换算 MiB，ID 为稳定的 JavaScript 安全整数。公共站点不会仅因公开访问就标记 free；free 对应上游明确的免流属性。字幕、UC、UHD 仅按明确的标题标识推断，不确定时不标记。

## 优先级与标签

- 源优先级：0–9999，越小越优先。旧源默认 100；新增 Jackett 默认 200。同级保留原配置及上游顺序。
- 分类标签：逗号分隔，支持源列表筛选，不参与资源排序。
- 去重：同哈希优先保留优先级更高源的整条记录，不盲目合并互相冲突的属性。支持十六进制与 Base32 BTIH 等价去重、ED2K 及既有标题回退。
- 接入设置 → 资源返回顺序：默认全部“不参与排序”。可设置免流、中字、UC、UHD 的优先/靠后并上下调整顺序。开启后先比较标签，再比较源优先级，不过滤资源；所有条件相同保留原顺序。
- 改名称、标签或优先级不作废源连接历史；改地址、请求头、超时、启停、类型、Jackett 站点或密钥会使旧诊断失效。旧版通用源历史指纹保持兼容。

Byte-Muse 会使用自己的过滤和排序再次选择资源，不能用 BM-BT 返回顺序承诺其订阅选择。2026-11-07 只读核对的现有实例 DEFAULT_SORT 为 `free,chinese,uc,!uc,site,seeders,!uhd,uhd`，默认 `exclude_uhd=true`、`MAIN_SITE=ALL`。同为 UC 时仍比较免流、中字、站点和做种数；所有比较项相同时保留输入顺序，未按大小额外排序。相反标签规则重复没有增加有效偏好。本次不修改 Byte-Muse 配置。

## 接口增量

源配置增加 `source_type`（generic/jackett）、`priority`、`tags`、`jackett_indexer` 和只写 `jackett_api_key`，响应增加 `has_jackett_api_key`。PUT 支持保留未提交的字段，旧调用方式继续可用。

受管理登录保护的新接口：

- `POST /api/jackett/indexers`：接收基础地址、可选 source_id、API Key 和请求头，返回已配置站点 id/name；已有源可复用保存的密钥。
- `POST /api/result-preferences`：接收 `{"result_preferences": ["chinese", "uc"]}`；空数组关闭。`!` 表示靠后，同一标签不可重复或同时配置相反规则。
- `/api/test` 增加结果来源 `provenance`、排序去重 `merge`、源 `outcome`、`indexers` 和 `skipped_count`；统计接口相应增加部分状态及站点诊断。

公开 `/api/torrents`、`/bt/api` 保持 `{data: [...]}`，不附带内部诊断或新凭据。配置以原目录原子保存，历史沿用原 SQLite，无表迁移。
