# db_online 部署及 BM-BT 接入验收

2026-11-07（Asia/Shanghai），按用户提供的第三方 Compose 调整并在 OVH 部署。BM-BT 主程序继续运行正式 1.4.0 固定摘要，接入通过独立适配器实现。

## 部署

- 版本：db_online `1.16.102`，应用报告构建提交 `064be7cc`。
- 应用镜像：`dbonline/db_online@sha256:da75ba3ee99d3d4360a78caa0edcb0ccd62ecb0c443fb87c365976e850186b5b`。
- 数据库：独立 PostgreSQL 16，镜像 `postgres@sha256:aa6cb33cf4c19c765cefcf48d96176258800870a9a1e930ad126200f9d825139`。
- 目录：OVH `/root/docker/db-online`，Compose 项目 `db-online`。
- 应用入口：`http://100.106.157.3:9090/`，需要 Tailscale；也绑定服务器 loopback。没有新增公网监听。
- 数据库和适配器没有宿主机端口。PostgreSQL 只连接独立内部网络，应用及适配器接 BM-BT 现有网络。
- 独立数据库随机密码；应用启用本地访问密钥并配置独立 API Key。实际访问数据仅保存在服务器私密配置及本机被忽略的私密文件中。
- 新增三个容器：`db_online`、`db_online_postgres`、`db_online_bt_adapter`。三者最终均 healthy，无 OOM。

可复用文件位于 `deploy/db-online/`：Compose、无真实密钥的环境模板、适配器 Dockerfile／源码／测试和部署说明。数据、缓存、日志和数据库分别持久挂载；设置了 CPU／内存限额和 Docker 日志轮转。

## 接入方式与结果

第三方 `/api/search?q=...` 返回影片资料，不能直接作为 BM-BT 的 `data: [...]` 种子结果。完整 `/api/video/{code}` 返回 `magnets` 和 `ed2ks`，适配器将其转换成 Byte-Muse 所需字段，并以 52 位整数生成稳定资源 ID。常见番号直查一部影片，普通文本最多展开第一页前三部。

BM-BT 已新增并启用源：

```text
名称：DB Online (JavDB)
ID：a4d1d9ff
URL：http://db_online_bt_adapter:9091/api/torrents
方法：GET
关键词字段：keyword
超时：30 秒
请求头：空
```

| 实测 | 结果 |
|---|---|
| 新源 `SSIS-586` / `ssis586` | 各 17 条，15 条磁力、2 条 ED2K |
| 新源 `IPX-451` | 18 条 |
| 新源不存在的 `ZZZ-9999999` | 成功空列表，区别于请求失败 |
| 中文演员名样本 | 成功零条；不能宣称新源支持完整演员作品搜索 |
| 三源 `SSIS-586` | AVDB 8、修仙 6、DB Online 17；合并去重后 17 条 |
| BM-BT 实际浏览器 | 三源概览、四工作页、360／390／768／1440 宽通过，零未捕获 JS 异常 |
| Byte-Muse v1.32.0 实际网页 | `SSIS-586`、`ssis586` 各显示相同 17 条结果；聚合端收到两个标准化关键词，均为三源 complete |

最初的适配器使用字符串 ID，Byte-Muse 实际网页返回空列表。通过读取实际 Torrent schema 定位为其要求整数 ID，临时停用新增源后修正；补充必需字段契约测试，在真实 Byte-Muse 模型逐条验证全部 17 条，并重新完成实际网页验收后启用。该过程中原两源的配置未改，BM-BT 没有重启。

适配器本地及实际运行镜像中各通过 11 项测试：外部契约类型、有限编号转换、磁力／ED2K 映射与去重、非法大小、空关键词、查询上限、未找到与错误的区分、部分详情失败、超时和错误脱敏。上游 401／非 JSON／无效结构不会被伪装为成功零条。适配器运行镜像仅在 OVH 本地构建，没有推送公共镜像。

## 第三方新功能检查

JavDB 上游 Authorization 保持为空，实际 `/api/subs/tags` following 查询成功返回 2 部影片；本地应用登录与上游 Authorization 相互独立。Tailscale 浏览器已完成本地访问密钥登录并进入 following。
