# 已发现标签与返回顺序

BM-BT 1.6.0，2026-11-07。

## 使用

“设置 → 已发现的资源标签”按源展示缓存的标签、分类和风格，可按来源及文字筛选。每项保留原始字段和值，显示累计命中次数，提示最近成功查询时间。点击标签将该源、该字段的文字规则加入排序草稿；需要跨源匹配时，可在下方手动选择“全部数据源”和“任意标签字段”。保存返回顺序后，下次查询生效。

普通聚合 API 和管理测试都从成功响应的去重前资源中累计标签，包括最终因去重而丢弃的资源。失败响应不更新目录；成功但没有文字标签的源显示独立说明。刷新列表只读取本地缓存，不会向上游搜索或扫库。当前接入源没有已验证的完整磁链标签目录；DB Online following 的影片分类不纳入这个目录。

缓存保存在持久化数据卷的 `/data/resource-labels.sqlite3`，与配置和请求历史分开。每源最多200项，全局最多5000项，90天未再次发现的标签清理；容量满时优先保留近期发现、同时间累计命中更多的标签。次数包括多次搜索的重复命中，不是独立资源总数。页面刷新及应用重启后仍可读取；只会展示当前源请求配置对应的缓存。修改源地址、请求头、超时、启用状态、站点或密钥会失效，改名、优先级、源管理分类标签不会失效。删除源会清理其缓存及只适用于该源的排序规则。

## 排序

原有免流、中字、UC、UHD 属性与新文字标签规则处于同一有序队列，最多24条。每条可选择优先或靠后，通过上移、下移调整比较顺序。例如：

1. 字幕优先，全部源、任意标签字段。
2. 无码破解优先，全部源、任意标签字段。
3. UHD靠后。
4. 条件相同按源优先级、源配置顺序和资源原顺序排列。

规则逐项比较，先出现的规则优先于后面的规则。文字规则按完整值匹配，使用 Unicode NFKC、casefold 和空白规范化忽略全角半角、大小写及多余空白；不做包含匹配、不自动猜测同义词。`tags`、`labels`、`category`、`categories`、`genres` 可单独限定，也可选择任意字段；可限定单源或全部源。相同来源、字段与规范化值只允许一条规则，反方向重复也会被拒绝。

先按原有源优先级选择去重胜出记录，再执行排序规则；不合并重复资源的冲突标签，不因标签偏好替换胜出来源。缓存只是选择器的数据来源，排序只查看每条最终保留资源的实际字段。没有标签的资源照常保留。未配置规则时行为保持原样，原有字符串形式配置保持兼容。

搜索测试的“排序与去重说明”显示本次请求使用的规则快照，资源卡片展开“查看排序依据”可逐条查看命中结果。设置变更不改写旧测试结果。公开 `/api/torrents`、`/bt/api` 仍只返回 `{data: [...]}`，不附带内部命中诊断字段。Byte-Muse仍会按自身规则过滤、排序，BM-BT顺序不能保证最终订阅选择。

## 兼容与边界

新增已登录管理接口 `GET /api/resource-labels`，返回按源的已发现标签。API Key 搜索保护、原登录Cookie、源配置、请求历史、Jackett已选站点保持原有流程。标签缓存出错时搜索照常返回，页面单独显示缓存问题；读取失败保留页面上次快照并支持重试。

标签仅保存允许的字段与有上限的纯文字值，不保存查询词、资源体、源URL、请求头或凭据。链接、磁链、凭据赋值式文字、控制字符和过长内容不会作为标签存储或渲染；界面使用文字节点。缓存和诊断均受管理登录保护。源请求配置变更以及变更后回切，旧请求的迟到响应不会重新写入当前目录。
