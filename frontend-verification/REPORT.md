## 设计与范围

使用 frontend-design 和 Impeccable。用户从三套可交互代码原型中明确「选1：素白运行台」。最终为蓝白浅色界面与横向四页导航：运行概览（默认）、数据源、搜索测试、接入设置。概览依次呈现指标、趋势与请求结果构成、源响应历史、最近请求；两个源已有完整信息层级，十个以内使用同一网格扩展。手机重排同一组功能，源编辑保留原生 dialog。

产品事实见 `PRODUCT.md`，方向记录见 `docs/frontend.brief.md`，最终设计规范见 `DESIGN.md`。视觉依据是用户选定的 `prototypes/dashboard/?v=1` 与 `screenshots/dashboard/style-1-desktop.jpg`；本轮延续该代码原型，不将废弃石墨方向的 seed/comps 当成当前验收依据。

页面和行为拆分至共享 `theme.css`、`dashboard.css`、`console.js`、`login.js`。后端增加静态资源挂载、真实统计记录和已认证的 `/api/stats`；原有搜索响应格式、聚合去重、接口别名与 Cookie 签名机制保持兼容。源配置增加向后兼容的持久化 `config_revision`，请求配置变化时更新，防止改动并恢复配置后，旧的在途请求重新成为当前状态。

## 统计口径与保存

`app/stats.py` 使用 `${DATA_DIR}/requests.sqlite3`（SQLite WAL）。记录功能启用后实际完成的 `/api/test`、`/api/torrents`、`/bt/api` 请求；没有补录历史，也不自动向源站轮询。完整成功、部分成功、全部失败按各目标源的实际结果计算，不能由聚合接口 HTTP 200 推断。无目标源不计为请求，无记录时成功率与耗时显示「—」。

提供今天／最近七天、请求数／耗时趋势、平均与 P95 耗时、原始／去重结果数量、异常筛选和游标分页。日期按浏览器偏移量分桶；每页20条，界面先展示6条，展开缓存后可继续加载。源历史最多展示30次响应，并由配置指纹和修订号隔离；配置修改后旧诊断立即失效，请求历史本身仍保留。

保留最近30天、最多50,000条，随新请求清理，重启后可读取。保存关键词、源 ID／名称、结果数量、耗时、状态码和归一化错误；不保存请求头、源 URL、响应正文或原始错误文本。统计写入失败不阻断搜索，界面明确提示统计存储异常。统计读取失败保留上次数据及其原有时间范围，并提供重试；异步响应使用请求序号保护，不能覆盖更新的配置或范围。
